### 1.2 spec 漏了一处：**报备的安抚话术**

spec §6.5 划的范围是：

> 3c **只负责 `客服点发送` 和 `AI直发` 两种去向**。

**`报备` 没人管。** 而演示里报备那条路**也要自动发一句话** ——

亲实在抱歉让您久等，赠品的事我立刻帮您核实，尽快答复您～

**它的硬约束是「不含承诺」** —— 也就是不许出现时限、不许出现「已 + 动作」。
理由和转交话术一样：这句话是在客服点发送**之前**就出去了的，
说死了后面就收不回来。

**要定的是**：这句是 3c 生成，还是像 `转交话术表` 那样**固定表**？

我倾向**固定表**（和 `转交话术表` 同构，放 `handover.py` 旁边或 `llm/` 里）：
它是「不含承诺」的兜底句，生成的意义不大，而每次生成一次就多赌一次「别说过头」。
**但这条要你定**，因为它是模型线内部的分工。

## 二 · 认诉求（节点 3.5）

### 2.1 它是什么

`docs/一句话进来的流程.md` 的「节点 3.5」：

| 项 | 内容 |
|---|---|
| 做什么 | 判这条消息**属于**已有的哪个诉求；不属于任何已有的 → 起一个新诉求 |
| 输入 | 一条消息 ＋ 本会话当前未解决的诉求清单 |
| 输出 | 诉求归属（已有的某个 ／ 新建） |
| 选型 | 模型。链路里的**第七个模型位置** |

**为什么不能并进 `拆主张`。** 催促可能**拆不出任何主张** ——「还要多久」不是一个
「能独立处置的事实点」，按 v8 §二该拆出零条。但它的归属是必须的：
H2 的窗口要它、G4 防重复要它、小卡要它。

> **归属问题在主张列表为空时依然存在，所以不能靠 `拆主张` 的输出来带。**

### 2.2 三个词的约定（`一句话进来的流程.md` 的术语节）

**这是地基，别混：**

| 词 | 定义 | 粒度 | 谁定 |
|---|---|---|---|
| **诉求** | 顾客要办的那一件事 | **可跨轮、跨天** | 装配层 |
| **轮** | 围绕**同一诉求**、买卖双方往来的**多条**消息 | 跨消息、跨双方 | `认诉求` ＋ 切轮 |
| **主张** | **一条消息里**一个能独立处置的事实点 | 消息内，N 条 | `拆主张` |

包含关系：**诉求 ⊃ 轮 ⊃ 主张**。

#### ⚠️ 已核实：`permissions` 的「诉求」是**另一个东西**，别当成一条链

> 这一格原先是「动手前先确认」。**2026-10-01 已核**，结论是**不能接**。

`permissions.py:434` 的 `认权限(主张: str, 权限矩阵) -> 权限条目 | None`，
文档串写「把一条主张认到某个**诉求条目**上」；`test_permissions.py:25` 的分节
标题更是直接写「**认诉求（认权限）**」。**但那是同名不同物：**

| | `permissions` 的「诉求条目」 | 本单的「诉求」（节点 3.5） |
|---|---|---|
| 是什么 | **权限矩阵的一行**（补发／换货／价差） | **顾客要办的那一件事** |
| 输入 | 一条**主张** | 一条**消息** ＋ 已有诉求清单 |
| 输出 | `权限条目` 或 `None` | 诉求标签（已有的某个／新建的） |
| **认不出时** | `未列明` —— 「这不是权限问题」，继续第 3 层 | **新建一个诉求** —— 「这是件新事」 |
| 主张为空时 | 无所谓（输入本来就是主张） | **仍必须给归属** |
| 选型 | 关键词（第 2 个模型位） | 模型（第 7 个模型位） |

**「认不出时」那一格正好相反，这是最要命的。** 拿 `认权限` 的 `None`
当「没有诉求」，会让每一句催促都变成一个新诉求 —— 轮次越切越碎。

**所以：两个东西，两条路，不要接。** 本单的 `认诉求` 输出是给切轮分组用的
（§三），`认权限` 的输入是主张（第 2 层），中间没有边。

⚠️ **`诉求` 现在只是文档里的词，代码里没有对应的类型。** 全项目 grep
`诉求`，命中的全是注释和测试分节标题（`permissions.py:472`、
`test_permissions.py:25`），**没有一处是类型定义或实现** —— 上面那张表说的
就是这两个命中。要不要给它一个 `dataclass`、还是就用字符串标签，你定 ——
但**定了要写下来**，因为「未解决诉求清单」
要跨消息存活（见下条）。

### 2.3 状态放哪

「本会话当前未解决的诉求清单」是**会话级状态**（节点 0 的「会话状态对象」那一条：
「顾客情况、承诺时限、已发出的话术都要跨消息存活」）。

**它归装配层，归接口线**（`app/data/装配.py`，2026-10-01 已拍板）。
所以 `认诉求` 是纯函数：**清单由调用方传进来，你不要自己存**。

⚠️ **别在 `llm/` 里做缓存或全局状态。** 那会让 `认诉求` 从「同样输入同样输出」
变成「取决于这个进程之前跑过什么」—— 留痕就再也解释不了某一轮为什么判成那样。

### 2.4 冻结的签名

```python
认诉求(消息文本: str, 已有诉求: Sequence[str]) -> str
```

返回**诉求标签**：命中了就原样返回清单里的那一个，没命中就返回一个新标签。
**标签的措辞就是它的身份** —— 返回时别改写、别归一化（「补发」和「补发赠品」
是两个诉求，会分出两轮）。

**接口线按这个签名先搭架子**，和 A 单的三个签名一样。

## 三 · 切轮拆分 —— 附带收回一个已经说出去的承诺

### 3.1 拆哪一半

`一句话进来的流程.md` 节点 3.5 的「顺序影响」：

> `切轮` 因此一分为二：判归属的那半交给本节点，**按归属标签分组**的那半留在
> `切轮` 里，仍是纯规则。

现在 `pipeline.切轮` 是「买家发言开始一轮，客服或 AI 发言结束当前轮」。
拆完之后分组依据多一条：**同一条诉求内的消息才归同一轮**。

### 3.2 ⚠️ 这条把一个承诺收回了

`pipeline.切轮` 的文档串现在写着：

> **防抖不在这里做。** 这条函数是纯的（同一输入必得同一输出，可重放）；

而整段「规则层可重放」的论证**建立在它之上**。`认诉求` 进来之后，
可重放的范围缩到「**切轮之后的**规则层」。

**这不是加个模型位，是改一句已经写出去的承诺。** 文档
`一句话进来的流程.md` 已经记了这一条，但**代码里那句话还在** ——
改代码时顺手把它改掉，别让它继续说自己是纯的。

⚠️ 顺带核一下 `docs/面试.md` 的「规则层可重放」那一段 ——
措辞现在要跟着收窄。**那是文档线的活，不是你的**，但别在面试里说成
「整条链路可重放」。

### 3.3 签名怎么改（这是接缝）

**接口线在调它**（`轮次 = 请求.轮次 或 切轮(消息)[-1]`）。改签名要让调用方能跟上。

建议**加参数而不是改参数**：

```python
切轮(消息: Sequence[轮消息], 归属: Mapping[int, str] | None = None) -> list[轮次]
```

`归属=None` 时退回现在的纯结构切法。三个好处：

- 接口线现在写的调用**不用改**就能继续跑（演示有退路）
- 归属判不出来时（模型挂了、超时）不会整条链断掉
- 「切轮仍然是纯函数」这句话**在 `归属` 给定之后依然成立** —— 收回的只是
  「不需要额外输入」，不是「同样输入同样输出」

**键用什么你定**（消息序号还是别的），定了写进文档串。
