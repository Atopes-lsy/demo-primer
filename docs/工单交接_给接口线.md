## 一 · 会话列表的 fetch —— **唯一没做的一件**，而且它的理由变了

`开发步骤.md` 步骤 1 的完成标准写的是「返回演示数据；把 `App.tsx` 的左侧列表
换成 fetch 它，界面照样显示」。**到现在还是没做**：

- `App.tsx:8` 仍是 `import { agent, sessions as seedSessions, shopMetrics, 先例库指标 } from './data'`
- `App.tsx:78` 仍是 `useState<Session[]>(seedSessions)`
- 前端打 `/api/会话列表` 的 fetch 出现 **0 次**

### ⚠️ 但「跨域坑压着」这个说法**已经不成立了** —— 它变成了「哑的」

写这单时那节的论证是「五分钟的接口上暴露跨域坑，比在判定接口上暴露便宜得多」。
**接口线后来把 `/api/判定` 也接上了**（`App.tsx:173` 调 `取判定`），
所以那条路径现在已经在跑。

**可它测不出东西来。** `判定.ts` 的 `取判定` 是这么写的：任何失败都返回 `null`，
不抛 —— 它自己的注释：「后端没起、超时、404、响应不是合法 JSON —— 对调用方
都是同一件事：这一轮拿不到，用剧本的」。

于是：**代理配错、CORS 被拦，右栏会照样显示** —— 每一块都回落成剧本里的值。
屏幕上「看着全对」。这不是假想，这是 `判定.ts` 刻意写的兜底，
而**兜底和「接口真的通了」长得一模一样**。

### 所以这一步的做法要换：别靠看右栏判断

**左侧列表是唯一的无兜底路径** —— 它全有或全无：138 个会话显示出来，或者空白。
没有剧本可回落，没有「看着对」的中间态。

顺序因此是：**先让左侧列表 fetch 出来**（代理 ＋ CORS 同时被证明），
这之后再谈 `/api/判定` 的结果为什么长这样。

**做法**：这步要**前端线**改 `App.tsx` 那两行 import 和 `useState`，
你这边什么都不用动，服务已经在了。别自己去改 `App.tsx`（那是前端线的文件）。

**你负责的是验证**：`vite dev` 起来后左侧列表显示全部会话 —— **不是**空白、
**不是** CORS 报错。

## 三 · 装配层 `app/data/装配.py` ✅ 已落地

> **已做**：`app/data/装配.py` ＋ `tests/test_装配.py`（17 个用例）。
> 下面留着，因为三条硬约束仍然是改它时的判据。

**写这单时没有任何东西造那五行**；`pipeline.组装顾客情况` 存在，但它的 `基础行`
入参没有产出者。现在产出者就是这一层。

```python
装配顾客情况(会话: schemas.Session, 本轮) -> list[pipeline.顾客情况行]
```

返回**固定五个** `顾客情况行`，标签照 `pipeline.顾客情况五行`，**顺序不能改**。

| 标签 | 从哪来 |
|---|---|
| 这是谁 | `会话.订单` 等会话级信息 |
| 这次要什么 | 本轮买家消息 |
| 答应过什么 | **扫客服消息找最晚一条未兑现的承诺**，并解析出 `时限` |
| 办过什么 | `会话.工单`（补发换货／物流／不良反应） |
| 这单 | `会话.订单`（货号、状态） |

### 三条硬约束

⚠️ **`时限` 必须填，且必须是 ISO 8601 字符串。** H3 就是读它比时间的。
填不上，H3 永远不命中 —— 而「H3 不命中」看起来和「今天没逾期」**一模一样**，
演示当天才发现就晚了。演示里那句是 `剧本.ts` 的 `承诺话术 = '48 小时内发出'`。

⚠️ **`警示` 不要在这一层填。** 它是 H3 的**输出**，由 `pipeline.组装顾客情况`
回填。这层填了会成环 —— 那个函数的文档串专门解释了三步顺序为什么必须是单向的。

⚠️ **解析放在这一层**（`pipeline.顾客情况行` 的文档串定的）：规则解析极脆，
LLM 解析又把模型塞到了 H3 前面，而 H3 的前提是「纯规则、微秒级」。
所以「自然语言 → 结构化」在这里做完，H3 只读 `时限` 做比较。

**不是每轮都重算**：`pipeline.按会话缓存` 钉死了「这是谁」和「这单」是会话级快照，
只有另外三行每轮重读。别把五行都当每轮算 —— 除了浪费，留痕里也解释不了
「为什么这一轮的值和上一轮不同」。

### 「未解决诉求清单」要存，但**别存成 `认权限` 的结果**

B 单的 `认诉求` 要一份「本会话当前未解决的诉求清单」（跨消息存活，归你这层）。
`permissions.认权限` 恰好也返回一个叫「诉求条目」的东西 —— **别接错**：

| | `permissions` 的「诉求条目」 | 节点 3.5 的「诉求」 |
|---|---|---|
| 是什么 | **权限矩阵的一行**（补发／换货／价差） | **顾客要办的那一件事** |
| 输入 | 一条**主张** | 一条**消息** ＋ 已有诉求清单 |
| 输出 | `权限条目` 或 `None` | 诉求标签（已有的某个／新建的） |
| **认不出时** | `未列明` —— 「这不是权限问题」，继续第 3 层 | **新建一个诉求** —— 「这是件新事」 |
| 主张为空时 | 无所谓（输入本来就是主张） | **仍必须给归属**（催促拆不出主张） |
| 选型 | 关键词（第 2 个模型位） | 模型（第 7 个模型位） |

**认不出时的行为正好相反**，这是最要命的一格：拿 `认权限` 的 `None` 当
「没有诉求」，会让每一句催促都变成「新诉求」，轮次越切越碎。

⚠️ **清单要能存下「一句话都没拆出主张」的诉求。** 催促（「还要多久」）按 v8 §二
拆出**零条**主张，但它必须有归属 —— H2 的窗口要它、G4 防重复要它、小卡要它。
清单如果只从 `拆主张` 的输出来建，这一类诉求会整个丢失，**而丢的是「顾客催了
两次」这个事实** —— 恰恰是 G4 要拦的那个。

## 四 · 路由 `app/api/判定.py` ✅ 已落地

> **已做**：`app/api/判定.py` ＋ `tests/test_判定.py`（33 个用例）。
> 它比下面这份提纲还多做了一件事：**三个模型位走 `Depends` 而不是直连 `import`**，
> 否则每跑一次测试都要花五六次真 API 调用（`deps.py` 文件头记着理由）。

`api/路由.py` 的文件头自己写着「`POST /api/判定` 是步骤 2，写在另一个模块里」。
按那句话新开一个模块，别往 `路由.py` 里塞。

### 顺序

```
1  会话 = 装.找(请求.会话ID)                    → None 就 404，别返回空判定
2  轮次 = 请求.轮次 或 切轮(消息)[-1]
3  安全事件 = 扫输入(本轮买家文本)
4  基础行 = 装配顾客情况(会话, 本轮)
5  触发列表 = 硬触发(文本们, 当前时间, 承诺时限=…, 订单状态=…,
                    重复要求=…, 认不信任函数=…)
6  顾客情况 = 组装顾客情况(基础行, 触发列表)      ← 回填「警示」
7  主张列表 = 拆主张(本轮买家文本, 顾客情况)      ← 模型线
8  六源 = {m: 查六源(m, 会话, 商品表) for m in 主张列表}   ← 模型线
9  判成 = 三层判定(主张列表, 触发列表, 六源=六源, 顾客情况=…,
                  口径表=…, 认口径函数=…)          ← 模型线
10 判成 = 收敛(判成)
11 组响应
```

⚠️ **4 和 5 的顺序不能换。** H3 的输入（`时限`）来自第 4 步，H3 在第 5 步算，
`警示` 在第 6 步回填。三步单向无环。

⚠️ **`当前时间` 用 `请求.当前时间`，省了才取服务器时间。** 契约说显式传是为了回放。
演示当天的「今天」是 **`2026-09-29`**，不是真实日期（`剧本.ts` 的 `演示今天`）。

⚠️ **`1` 的 404 别写成空判定。** 「会话不存在」和「这个会话没触发任何东西」
在界面上都是右栏空白，但前者是前端传错了 ID —— 返回空判定的话，
排查方向会指向判定逻辑，而那是对的。

### 组响应

- `Disposition.id` 格式 **`${会话ID}-${轮次}-${序号}`**，序号从 1。
  相邻两轮的第 1 条主张都是 `-1`，**但轮次不同所以不冲突** —— 见下条。
- `Advice.形态` 由 `pipeline.主卡形态` 取本轮最高态再映射。
  **`AI直发` 不上主卡**（它不需要客服动手），只进 `已代发`。
- `Advice.依据` **只放查到的**（`源记录.exists=True` 的那些）。没查到的来源
  由**前端**按六源补空位 —— 你不要替它补，补了两边补的数量对不上就变成漏列。
- **`已代发` 只在 `主卡` 里，顶层没有。** 顶层再放一份就是同一份数据传两遍，
  两份一旦不同步，右栏两处会显示不一样的内容，**而两处都看着对**。
