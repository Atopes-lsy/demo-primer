## 一 · 「同时开几个 coding session，各负责什么」

### 1.1 先看考点

问「开几个」，想听的不是数字，是**你怎么控制并行带来的冲突**。

数字答大了反而扣分：说不出边界的人开 8 个 session，听起来像失控。
答「3 条 + 1 条决策」并讲清文件所有权，比答「5 个」高一档。

**追问一定会落在两处**：线之间冲突了怎么办、你怎么知道某条线的产出是对的。
两处答不上来，前面报的数字全是负分。

### 1.2 回答（可直接背）

> 同时开 3 条写代码的，外加 1 条不写代码的决策线。
>
> 上限不是机器，是两个约束：**一个文件同一时刻只能有一个写入者**，
> 以及**每条线要用的接口必须已经冻结**。所以我先用半天把 JSON 契约定死 ——
> 前后端字段名逐字对应、有测试盯着 —— 契约定死之后，才切出三条文件不重叠的线。
>
> 接口线做主链路；模型线做拆主张／依据检索／话术生成，这三个都落在新目录里，
> 天然不跟接口线抢文件；前端线先做界面，接口一上就切数据源。
> 第四条不写代码，专门去问规格里没定的那两条 —— 决策塞进编码 session 让它自己猜，
> 是最贵的错，因为猜错之后建在上面的东西全得推倒。
>
> 代价是一条契约文件只能单点写：`types/index.ts` 被后端测试**直接解析**，
> 谁都能改会让前后端两条线同时变红，所以我把它划给接口线独占，前端线要改就提给它。

### 1.3 四条线

| # | session | 独占哪些文件 | 干什么 |
|---|---|---|---|
| 1 | **接口线**（主链路） | `backend/app/main.py`、`app/api/`（路由、`deps.py`）、`app/data/装载器.py` | 步骤 1–2：骨架、数据装载、`POST /api/判定` |
| 2 | **模型线** | `backend/app/检索/`、`backend/app/llm/`（两个**新目录**） | 步骤 3：建索引 → 拆主张 → 话术生成 |
| 3 | **前端右栏线** | `frontend/src/components/plugin/`、`session/`、`data/` | 先清界面项，接口一上就切数据源 |
| 4 | **决策/文档线**（不写代码） | `docs/` | 问规格里没定的条目；修文档漂移 |

三条编码线的文件集**两两不相交**，这是切法的全部依据 —— 不是按「功能模块」切，
是按「谁写哪个文件」切。

### 1.4 为什么是 3 不是 5

两个硬约束，不是审美：

**1 · 一个文件同一时刻只能有一个写入者。**

这个项目里有一条特别阴的耦合：`tests/test_schemas.py` 会**真的去解析**
`frontend/src/types/index.ts`，逐字段核对 —— 不是在这儿手抄一份再跟自己比。

后果是前端线改 `types/index.ts`，**后端**的测试会变红。
所以这个文件必须单点写：划给接口线独占，前端线提需求给它改。

**2 · 每条线要用的接口必须已经冻结。**

这正是步骤 0 干的事，也是现在能开三条的**唯一原因**。
契约定在前面是半天，定在后面是每条线各返工一遍。

### 1.5 排期与汇合点

**三线并行（现在）**：接口线做步骤 1 → 2；模型线从建索引开始（最可能出意外的一块，
最该早开）；前端线清界面项。三条互不碰文件，靠 `schemas.py` 对齐。

**汇合点**：`POST /api/判定` 通过完成标准那一刻，**前端线立刻切过去接接口**。
这是全局唯一的串行依赖 —— 承认它比硬并行重要，硬并行只会返工。

前端线腾出的位置由步骤 4（动作接口）顶上，仍然是三条。

**决策线全程常开**，但它不产出代码，也不占编码线的名额。

### 1.6 每条的闸门

各 session 收工前自己跑，别攒着：

```bash
cd backend && PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe -m pytest -q
cd frontend && npx tsc -b --force && npx oxlint src/
```

⚠️ 前端那条是 `tsc -b`，**不是 `--noEmit`**。根 `tsconfig.json` 是 solution 式的
（`"files": []` ＋ `references`），拿 `--noEmit` 打它等于什么都没查，**而且 exit 0** ——
会让人以为类型是干净的。

⚠️ `PYTHONIOENCODING=utf-8` 前缀必须带，否则中文控制台输出乱码，
看测试失败原因都得猜。

### 1.7 会被追问的

**「两条线冲突了怎么办？」**

三层防线，从便宜到贵：文件所有权（根本不碰同一个文件）→ 契约单点写入
（`types/index.ts`、`schemas.py` 各有唯一写入者）→ 后端测试当跨端裁判
（漂移不会让任何东西报错，只会让界面少显示一块，所以必须靠测试而不是靠肉眼）。

**「你怎么知道某条线的产出是对的？」**

每条线自带闸门，收工前跑自己的那条命令；跨端的部分由契约测试兜。
关键在于**闸门是每条线自己的** —— 攒到最后一起跑，出问题时已经分不清是哪条线的。

**「并行真的更快吗？」**

不是所有活都能并行。有一条串行依赖必须承认：前端接接口依赖判定接口存在。
硬并行只会返工。能并行的部分是由「契约已冻结 + 文件不重叠」切出来的，不是想并行就能并行。

**「为什么要专门一条不写代码的线？」**

规格里没定的条目，编码 session 不会停下来，它会自己猜一个然后往下建。
猜错返工的成本远大于单独问一次。

### 2.4 修文档漂移时核出来的四件事（旧文档里都没有）

这四条是**新发现**，不是「过期」—— 原来就没记过。面试讲「你怎么维护文档」时，
这四条比「我更新了表格」有料：

1. **`handover.py` 的自检从来没被执行过。** 校验写在模块导入时，但 `tests/` 下
   没有任何文件 import handover。**当前唯一一处「写了校验但没人验证」的地方。**
2. **现状下 `AI直发` 实际不可达。** `六源` 默认 `None` → 永远报「查不到」→
   一律客服点发送。第 3 层和权限矩阵**目前跑在空输入上** —— 有测试，
   但没在真数据上走过一遍。「测试全绿」不等于「链路通了」。
3. **模型位置有六个，不是三个。** 文档一直说「三步模型调用」，那是流水线上的；
   规则层里另有 `认口径`／`认权限`／`涉个体差异` 三个。**前三个错了不报错，
   只会静默判歪** —— 这类错最难查。
4. **`handover` 没接进判定路径。** 原计划「转交话术当成一类主张进同一张输出表」，
   实际做成了独立模块，`pipeline` 没 import 它。
